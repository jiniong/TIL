# 학습 노트 작성 템플릿

## 공통 양식

아래 양식을 복사해 사용합니다. 기록일은 실제 날짜를 아는 경우에만 작성하고, 출처에는 책 제목·영상 링크·직접 작성한 기록임을 표시합니다.

````markdown
# 문서 제목

- 분류: 독서 / 실습 / 질문 / 영상 중 하나
- 기록일: YYYY-MM-DD
- 갱신일: YYYY-MM-DD
- 주제: 검색할 핵심 개념
- 출처: 책 제목 / [영상 제목](URL) / 개인 학습 질문 / 직접 구현 및 실험 기록
- 상태: 개념 정리 / 진행 중 / 사용자 동작 보고 / 직접 실행 검증 등 실제 근거

## 목차

- [첫 번째 주제](#첫-번째-주제)
- [두 번째 주제](#두-번째-주제)

## 첫 번째 주제

설명과 학습 내용을 작성합니다.

### 세부 주제

- 필요한 항목을 정리합니다.

```text
코드나 실행 결과를 기록합니다.
```

## 두 번째 주제

설명과 학습 내용을 작성합니다.

## 관련 지식

- [관련 노트 제목](상대경로.md)

## 업데이트 기록

- YYYY-MM-DD: 새로 확인하거나 수정한 내용과 근거
````

## 작성 규칙

- 문서 제목은 H1(`#`) 하나만 사용하고, 본문은 H2(`##`)부터 순서대로 작성합니다.
- 목차에는 본문의 H2 제목을 연결합니다.
- 질문 노트는 `## 질문 1`, `## 답변 1`을 한 쌍으로 작성하고, 추가 질문은 번호를 늘립니다.
- 실습 노트는 배경·계획·구현·결과·시행착오 등 실제 기록이 있는 항목만 작성합니다.
- 출처를 알 수 없는 정보나 작성하지 않은 결론을 채워 넣지 않습니다.
- 코드는 언어를 지정한 코드 블록에 넣고, 비교 표는 한 행을 한 줄로 작성합니다.
- 저장소 이미지는 현재 파일 기준 상대 경로를 사용합니다. 원본 첨부가 없으면 파일이 없다는 사실을 텍스트로 남깁니다.

## 대화와 실습의 누적 기준

- 새 노트를 쓰기 전에 [주제별 색인](TOPICS.md)에서 같은 지식이 있는지 확인합니다.
- 같은 개념을 더 이해했으면 기존 노트를 보완하고 갱신일·업데이트 기록을 남깁니다.
- 새 환경에서 실제로 실험했거나 새로운 실패를 겪었으면 Did에 기록하고 관련 개념으로 연결합니다.
- 대화에서 나온 개념은 질문과 답변으로, 실습은 목표·환경·시도·결과·다음 확인으로 정리합니다.
- 기록일은 원래 학습 날짜를 유지합니다. 상태·주제·갱신일은 실제 확인할 수 있는 정보가 있을 때 추가합니다.
- 설명 예시, 사용자의 성공 보고, 소스 확인, 직접 실행 검증을 구분합니다. 완료되지 않은 실습은 남은 작업을 명시합니다.
- 추가한 노트는 전체 목차와 주제별 색인 양쪽에서 찾을 수 있게 합니다.
- 개념 수정은 이전 답변의 단순 누적보다 현재 이해가 본문에 드러나게 반영하고, 바뀐 이유는 업데이트 기록에 남깁니다.

## 긴 독서 노트 분리 규칙

- 독립된 주제가 여러 개이고 수백 줄에 이르면 기존 챕터 경계로 나눕니다.
- 원래 파일은 책 제목·출처·챕터 목차를 담은 진입점으로 유지합니다.
- 같은 이름의 폴더 아래에 `01.챕터 제목.md`, `02.챕터 제목.md` 순서로 저장합니다.
- 이미 챕터 폴더로 나뉜 책은 기존 구조를 유지하고 책 폴더에 `README.md` 목차를 둡니다.
- 챕터에는 책 목차로 돌아가는 링크를 추가합니다.
