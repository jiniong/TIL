## 목표와 환경

버튼을 누를 때마다 LED 상태를 한 번만 바꾸고, 이후 LED 세 개를 순환하는 실습이다.

- 당시 확인한 프로젝트: [Wokwi 버튼 실습](https://wokwi.com/projects/479012745115365377)
- 저장된 보드: ESP32-DevKitC V4
- 입력 방식: INPUT_PULLUP

## 입력과 눌림 순간

풀업 입력은 누르지 않았을 때 HIGH, GPIO와 GND가 연결되면 LOW가 된다.

~~~cpp
if (previous == HIGH && current == LOW) {
  status = (status + 1) % 2;
}
previous = current;
~~~

위 코드는 눌림 순간의 조건을 보여주는 부분 코드다. current == LOW만 검사하면 누르고 있는 동안 loop마다 반복 실행된다. 대화 중 previous = HIGH를 previous == HIGH로 수정했다. 대입과 비교는 구분해야 한다.

## 디바운싱

실제 버튼 접점은 한 번 눌러도 짧은 시간 동안 여러 번 상태가 바뀔 수 있다. 단순 직전 값과 안정적으로 확정한 값을 분리한다.

| 상태 | 용도 |
| --- | --- |
| previousReading | 직전에 읽은 원시 입력 |
| stableState | 안정 시간 이후 확정한 상태 |
| lastChangeTime | 원시 입력이 마지막으로 바뀐 시각 |
| debounceMs | 상태가 유지되어야 하는 시간, 대화 예시는 30ms |

1. 원시 값이 바뀌면 lastChangeTime 갱신
2. 같은 값이 debounceMs 이상 유지되는지 확인
3. 안정 상태가 HIGH에서 LOW로 바뀔 때만 이벤트 발생
4. 그 이벤트 안에서만 LED 인덱스·버튼 횟수 변경

previousTime을 loop마다 갱신하면 충분한 시간이 경과했다는 조건이 충족되기 어렵다. buttonCount도 loop마다 증가시키면 누름 횟수가 아니라 반복 횟수를 세게 된다.

## 배선에서 발견한 문제

| 당시 저장 상태 | 문제와 수정 방향 |
| --- | --- |
| GPIO35를 LED 출력으로 사용 | 일반 ESP32 입력 전용 핀이므로 GPIO25 등 출력 가능 핀 사용 |
| 버튼의 1.l과 1.r 연결 | 같은 내부 접점이므로 한쪽은 2.l 또는 2.r 그룹으로 이동 |
| LED 저항 220000Ω | 의도한 330Ω과 다른 값이므로 부품 값 재확인 |
| 5V 쪽에서 LED로 연결 | 코드가 가정한 active-high 배선과 맞는지 대조 |

Wokwi 버튼의 1.l/1.r은 한 그룹, 2.l/2.r은 다른 그룹이다. 누르면 두 그룹이 연결된다. [Wokwi 버튼 공식 문서](https://docs.wokwi.com/parts/wokwi-pushbutton)

## 검증 상태와 다음 작업

단일 LED 토글은 사용자가 구현했다고 보고했다. 이후 세 LED 순환용 배선·코드 수정안은 제시됐으나, 수정 회로의 컴파일·시뮬레이션 성공은 원문에서 확인하지 못했다.

- 버튼만 Serial로 읽어 HIGH·LOW 확인
- 각 LED를 단독으로 켜 출력 핀·극성 확인
- 통합 후 한 번 누름당 한 번만 전환되는지 확인
- 오래 누르기·빠른 연속 누르기에서 중복 이벤트 확인
