## 질문 1

Kubernetes 환경을 구성하는 프로젝트는 곧 Pod를 빌려주는 서비스일까?

## 답변 1

인프라를 준비하는 기능, 사용자의 작업 공간을 관리하는 기능, 실제 Pod를 배치·실행하는 기능을 구분한다.

| 계층 | 책임 |
| --- | --- |
| 인프라·플랫폼 도구 | 클러스터 준비, 네트워크·스토리지·Ingress 등 공통 기반 구성과 검증 |
| 워크스페이스 서비스 | 사용자 인증, 작업 공간 생성·종료 요청, 수명·사용량·권한 관리 |
| Kubernetes | 선언된 워크로드의 상태 유지, 적절한 Node 배치와 실행 |

~~~text
플랫폼 도구가 실행 기반 준비
        ↓
사용자가 워크스페이스 생성 요청
        ↓
워크스페이스 앱이 워크로드 생성·관리
        ↓
Kubernetes가 Node에 Pod 배치·실행
~~~

대화에서 분석한 도구는 클러스터와 공통 플랫폼을 준비하는 것이 주된 역할이었다. 사용자 요청마다 작업용 리소스를 만드는지는 상위 앱의 API·컨트롤러 코드를 별도로 확인해야 한다.

### 코드로 역할 확인하기

- 클러스터·네트워크·스토리지 생성 코드인지 확인
- 사용자 요청을 받는 API와 사용자별 리소스 매핑 확인
- Kubernetes에 어떤 종류의 워크로드를 만드는지 확인
- 생성뿐 아니라 삭제·복구·영속 저장소 수명도 확인

저장소에 배포 YAML이나 앱 이름이 있다는 사실만으로 사용자 대상 서비스가 완성됐다고 판단하지 않는다. 당시 분석은 저장소 기준이며 실제 운영 클러스터에 접속한 결과가 아니다.
