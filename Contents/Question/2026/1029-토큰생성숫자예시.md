## 질문 1

질문이 토큰으로 바뀌고 파라미터로 계산되어 다시 답변이 되는 과정을 숫자로 볼 수 있을까?

## 답변 1

아래 토큰 목록·벡터·가중치는 대화의 설명을 위해 만든 가상 값이다. 실제 모델의 토큰화나 내부 행렬을 추출한 결과가 아니다.

~~~text
"나는"
  → 토큰 ID [0]
  → 임베딩 [1, 2]
  → 문맥을 반영하는 여러 층의 계산
  → 다음 토큰별 점수
  → softmax 확률 → 선택 → 텍스트 복원
~~~

ID는 어휘 표의 이름표다. 번호 자체의 크기가 의미의 크기는 아니다. 실제로는 어텐션·신경망 층 등이 문맥을 반영하지만, 여기서는 중간 벡터를 [1, 2]라고 가정하고 출력 계산만 살펴본다.

### 다음 토큰의 점수

| 후보 | 가중치 | 계산 | 점수 |
| --- | --- | --- | ---: |
| 학생 | [1, 1] | 1×1 + 2×1 | 3 |
| 개발자 | [2, 0] | 1×2 + 2×0 | 2 |
| 입니다 | [0, 0] | 1×0 + 2×0 | 0 |

softmax는 각 점수에 지수함수를 적용한 뒤 합으로 나눈다.

~~~text
e³ + e² + e⁰ ≈ 28.47
학생: e³ / 합 ≈ 70.5%
개발자: e² / 합 ≈ 26.0%
입니다: e⁰ / 합 ≈ 3.5%
~~~

최댓값 선택을 가정하면 학생이 선택된다. 생성 설정에 따라 확률을 이용한 샘플링도 가능하다.

### 토큰을 붙이고 다시 계산

~~~text
[나는]                  → 학생 선택
[나는, 학생]            → 다음 계산에서 입니다 선택을 가정
[나는, 학생, 입니다]    → 다음 계산에서 종료 토큰 선택을 가정
~~~

입니다와 종료 토큰의 선택은 흐름을 설명하기 위한 가정이며 위 점수표 하나로 계산한 결과가 아니다. 실제 생성에서는 앞선 문맥과 새 토큰을 반영해 계산을 이어간다.

### 가중치 변경의 효과

개발자 후보의 가중치를 [2, 0]에서 [4, 0]으로 바꾸면 점수가 4로 바뀐다. 세 후보의 확률은 학생 약 26.5%, 개발자 약 72.1%, 입니다 약 1.3%가 된다.

이 예시는 숫자 변경이 출력 확률에 영향을 준다는 원리를 보여준다. 실제 모델에서 특정 파라미터 하나를 바꾸면 특정 단어만 제어된다는 뜻은 아니다.
