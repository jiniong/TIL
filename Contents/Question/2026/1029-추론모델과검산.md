## 질문 1

추론 모델도 다음 토큰을 고르는데 생각을 더 오래 한다는 것은 무슨 뜻일까?

## 답변 1

대표적으로는 최종 답변 전에 중간 계산을 더 생성하고, 그 결과를 다음 계산에 반영하며 연산을 더 수행한다는 뜻이다. 요청을 처리하는 동안 파라미터를 새로 학습한다는 뜻은 아니다.

~~~text
17 × 23
  → 17 × 20 = 340
  → 17 × 3 = 51
  → 340 + 51 = 391
  → 최종 답변
~~~

같은 다음 토큰 생성 방식이라도 문제 분해·검산·수정에 유용한 행동을 학습할 수 있다. 다만 모든 추론 시스템의 구현이 동일한 것은 아니다. [DeepSeek-R1 연구](https://arxiv.org/abs/2501.12948)

## 질문 2

검산도 토큰 생성이라면 틀렸다는 것을 어떻게 알까?

## 답변 2

모델이 정답을 보장하는 감각을 가진 것은 아니다. 다른 풀이와의 불일치, 조건 대입 결과, 도구 실행 결과 등에서 오류를 의심할 근거를 찾는 것이다.

| 방법 | 근거 | 한계 |
| --- | --- | --- |
| 자신의 풀이 재검토 | 학습된 패턴과 문맥 | 같은 오류를 놓칠 수 있음 |
| 다른 방법으로 계산 | 결과 비교 | 둘 다 틀릴 수 있음 |
| 코드·계산기 실행 | 실행 결과 | 식·코드 입력이 틀릴 수 있음 |
| 정형 검증 | 명시한 규칙 | 문제의 형식화가 틀릴 수 있음 |

“검산해 줘”라는 요청 문장이 매번 먼저 생성되어야 하는 것은 아니다. 모델이 다른 계산을 이어 쓰는 행동 자체가 검산을 수행하는 흐름이 될 수 있다. 별도 프로그램이 검증 도구를 호출하거나 재시도를 제어하는 구조도 구분한다.

## 질문 3

일반 모델에 검산하고 수정하라고 지시하면 추론 모델과 같아질까?

## 답변 3

비슷한 절차를 유도할 수 있지만, 지시를 이해하는 것과 실제 오류를 잘 찾아내는 능력은 다르다. 추가 학습과 실행 시 계산 예산이 성능에 영향을 준다. 일반 모델도 잘 풀 수 있고 추론 모델도 틀릴 수 있다.

품질을 판단할 때는 풀이 길이나 자기 확신보다 정답·테스트·외부 근거를 본다.
