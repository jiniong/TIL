## 질문 1

이미 만들어진 모델을 학습시킨다는 것은 무엇을 바꾸는 걸까?

## 답변 1

추론은 현재 가중치로 답변을 생성하는 과정이고, 학습은 손실을 줄이도록 학습 대상 가중치를 조정하는 과정이다. 대화를 나누거나 문서를 입력했다고 배포된 모델의 가중치가 자동으로 수정되는 것은 아니다.

~~~text
질문·모범 답변 데이터 준비
  → 토큰화·학습용 형식 구성
  → 모델이 정답 토큰에 부여한 확률 계산
  → 손실 계산 → 역전파 → 옵티마이저 업데이트
  → 체크포인트 또는 어댑터 저장
  → 평가 → 서빙에 새 버전 적용
~~~

## 질문 2

모든 가중치를 수정해야 할까? LoRA는 무엇일까?

## 답변 2

전체 파인튜닝은 원래 모델의 학습 대상 가중치를 수정한다. LoRA는 기반 가중치를 고정하고 작은 저랭크 행렬을 학습해 변화량을 더하는 방식이다.

~~~text
개념식: W_effective = W_base + ΔW
LoRA의 ΔW는 작은 두 행렬의 곱으로 표현
~~~

학습 대상과 옵티마이저 상태의 규모를 줄일 수 있지만, 기반 모델을 불러오고 연산할 자원은 여전히 필요하다. 어댑터는 어떤 기반 모델용인지 함께 관리해야 한다. [Hugging Face PEFT LoRA 문서](https://huggingface.co/docs/peft/main/en/conceptual_guides/lora)

대화에서 다룬 도구는 PyTorch, Transformers, TRL의 SFTTrainer, PEFT다. 여기서는 역할을 정리했으며 학습을 실제 실행하거나 모델을 배포한 기록은 없다. 실행 코드는 라이브러리 버전에 맞게 별도 검증해야 한다.

## 질문 3

새로운 사내 지식을 알려주려면 파인튜닝해야 할까?

## 답변 3

| 목적 | 먼저 구분할 접근 |
| --- | --- |
| 변경되는 문서의 최신 근거 제공 | 검색한 문서를 입력에 넣는 RAG |
| 응답 형식·분류 기준·일관된 행동 개선 | 예시 데이터 기반 SFT·LoRA 검토 |
| 같은 가중치로 더 많은 요청 처리 | vLLM 등 서빙 엔진과 운영 최적화 |

RAG는 입력 근거를 바꾸고, 학습은 학습 대상 숫자를 바꾸며, 엔진 최적화는 실행 방식을 조정한다. 목표에 맞는 평가 질문을 따로 준비해야 한다.
